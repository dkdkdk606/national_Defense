# 공고별 자격판정 결과 엑셀 생성 스킬

## 언제 사용
- 사용자가 지원사업/공고 관련 파일들(pdf, hwp, hwpx, zip 등)과 사업체 정보(txt 등)를 함께 제공하고
- "이 사업에 우리 사업체가 지원 가능한지 판단해줘", "정부사업 진행하려는데 어떻게 해야할지 알려줘", "공고별 자격판정 결과를 엑셀로 정리해줘" 라고 요청할 때

## 필요한 스킬 (미리 설치되어 있어야 함)
- pdf-tools (PDF 읽기/추출)
- hwpx-tools (HWP/HWPX 읽기, kordoc)
- xlsx-tools (엑셀 생성, openpyxl)

## 워크플로우

### 1단계: 업로드 파일 확인 및 분류
- 사용자가 올린 파일 목록에서 공고 관련 파일과 사업체 정보 파일을 구분
- 파일 형식(pdf/hwp/hwpx/txt/docx/xlsx 등) 확인
- 공고별로 파일 구분 (공고명·기관·공고번호·공고일·접수기간으로 같은 공고인지 판단)

### 2단계: 파일 읽기 (공고 내용 추출)
- pdf 파일: pdftotext, pypdf 등으로 텍스트 추출. 스캔 PDF면 OCR 시도 (tesseract). 안 되면 "미확인" 처리
- hwp/hwpx 파일: kordoc 으로 마크다운 추출
- txt 파일: 직접 읽기

### 3단계: 파악 및 파일 작성
# 공고 자격판정 결과 문서 템플릿 (공고별 상세)

이 마크다운은 지원사업/공고 파일을 분석한 결과를 **몇개의 공고든 1개의 엑셀파일로** 정리할 때 쓰는 템플릿이다.
요약 시트 외 각 공고 세부사항 공통 구조는 아래 순서로 고정한다.

1. 최종 판정
2. 공고 개요
3. 참가자격 대조
4. 필요 서류/액션 체크리스트

여러 공고를 한 번에 분석할 때는 개요/판정 기준이 같더라도 **같은 공고로 자동 합치지 않는다**.
공고명, 기관, 공고번호, 공고일/접수기간이 있으면 각 파일의 식별 정보로 함께 남긴다.

---

## 0. 시작 흐름 (자동 분석 워크플로우)

이 템플릿을 쓰는 분석의 시작은 보통 **사용자가 공고문들과 사업체 정보를 같이 올려주는 상황**이다.
아래 순서대로 자동 처리하는 것을 기본으로 한다.

### 0-1. 사용자가 올려준 자료 확인

- 사용자가 공고 관련 파일(공고문, 공고페이지, 과업지시서/제안요청서, 붙임 등)과 사업체 정보를 올리면,
  먼저 전체 업로드 파일 목록을 확인한다.
- 어떤 파일이 공고문이고 어떤 파일이 사업체 정보인지, 형식(pdf, hwp, hwpx, txt, docx, xlsx 등)이 무엇인지 함께 파악한다.

### 0-2. 파일 읽기에 필요한 스킬 자동 설치

- 업로드된 파일 형식에 따라 읽는 데 필요한 스킬이 다르면, 분석을 계속하기 위해 **필요한 스킬을 자동으로 설치**한다.
- 보통 아래 스킬이 후보가 된다.
  - pdf 읽기/추출이 필요하면: pdf 관련 스킬
  - hwp/hwpx 읽기가 필요하면: hwpx 관련 스킬
  - xlsx/엑셀 요약이 필요하면: 엑셀 관련 스킬
- 설치된 스킬은 이후 “파일 읽기 → 내용 추출 → 공고별 구분 → 대조/판정” 전 과정에서 바로 사용한다.

### 0-3. 공고별로 파일 구분

- 읽은 파일을 바탕으로 **공고 단위로 구분**한다.
- 한 공고에 여러 파일이 붙어 있을 수 있고, 여러 공고가 한 번에 올라올 수도 있다.
- 같은 공고인지 여부는 다음 정보로 판단한다.
  - 공고명
  - 기관/발주처
  - 공고번호/공고 제목/문서 제목
  - 공고일, 접수기간, 마감일
  - 계약명/사업명
- 위 정보가 서로 다르면 근거가 완전히 같아 보여도 **같은 공고로 자동 합치지 않는다**.

### 0-4. 공고별 분석

- 각 공고에 대해 아래 4개 섹션을 기준으로 분석한다.
  - 최종 판정
  - 공고 개요
  - 참가자격 대조
  - 필요 서류/액션 체크리스트
- 사업체/신청자 정보가 있으면 그 정보도 함께 반영해서 대조한다.
- 공고문/제출 자료에 없는 조건은 추측하지 않고 `확인 필요` 또는 `미확인`으로 남긴다.

### 0-5. 결과 출력 (엑셀, n+1 시트)

- 분석이 끝나면 결과를 엑셀 파일로 만든다.
- 시트 구성:
  - 1개의 **요약 시트**
  - 공고별로 **상세 시트** (공고 수만큼)
- 전체 시트 수는 **n개 공고 + 1 요약 시트 = n+1 시트**가 원칙이다.
- 요약 시트에는 각 공고의 식별정보와 최종 판정, 한 줄 판정 요약을 넣고,
  세부 대조/부족정보/서류 체크리스트는 각 공고별 상세 시트에 넣는다.

### 0-6. 질문은 아주 특수한 경우에만

- 기본적으로는 위 흐름을 최대한 자동으로 진행한다.
- 질문을 하는 경우는 아래처럼 **정말 필요한 경우에만**으로 제한한다.
  - 공고문/제출 자료가 너무 부실해서 어떤 공고인지, 어떤 조건인지 판단이 거의 안 되는 경우
  - 공고문을 보완해 주면 훨씬 정확히 판정할 수 있는데, 사용자에게 그 사실을 안내해야 하는 경우
- 질문을 할 때는 다음처럼 행동한다.
  - “지금 올려주신 자료만으로는 어떤 공고인지/무엇이 조건인지 판단이 어렵고, 이런 내용을 더 올려주시면 훨씬 정확히 판단할 수 있다”고 안내한다.
    - **이런 내용**은 최대한 자세하게 예시를 들어준다.
  - “지금 보충이 어렵다면, 일단 이 내용만 가지고 판단하겠다”고 밝히고 분석을 이어간다.
- 가급적 판단 자체를 멈추지 말고, 부족 정보가 있을 때는 `확인 필요`/ `미확인`으로 표시해서 자동 분석을 이어간다.

## 1. 최종 판정

### 최종 판정 표기

- `[지원 가능]` / `[지원 불가]` / `[조건부 가능/확인 필요]` / `[자료 부족/보류]`
- 위 분류만 사용하고, 애매한 결론은 함부로 내리지 않는다.
- 공고문이나 사용자 정보에 없는 조건은 단정하지 않고 `확인 필요`로 남긴다.

### 판정 요약

- 핵심 판정 이유 2~3줄로 적는다.
- 근거 문장/항 번호는 가능하면 함께 적는다.

형식 예시:

- 최종 판정: `[지원 가능]` (단, 신청제외 항목 확인 필요 시 `[조건부 가능]`)
- 판정 요약: (이유 2~3줄)

## 2. 공고 개요

공고 개요는 아래 항목을 **우선 순서로** 적는다.  
항목이 비어 있으면 비워 두고, 없는 내용을 추측해서 채우지 않는다.

### 표준 항목 (우선)

| 항목 | 설명 | 출처 우선순위 |
| --- | --- | --- |
| 계약명 | 사업/공사/용역 명칭 | 공고페이지(나라장터) > 공고문 본문 |
| 계약 주체 | 발주기관 / 입찰대행기관 / 보조사업자 / 계약 이행 주체 등 | 공고페이지 > 공고문 본문 > 붙임/유의사항 |
| 문서 번호 | 공고번호, 공고 제YYYY-XXX호 등 | 공고문 상단/공고페이지 상단 |
| 공고일 / 접수기간 | 공고일, 신청·제출·입찰 기간, 마감 일시 | 공고문 본문 > 공고페이지 |
| 용역기간 / 계약기간 | 착수일~완료일, 공사기간, 용역기간 등 | 공고문 본문 > 공고페이지 |
| 계약금액 | 기초금액, 추정금액, 추정가격, 부가세 포함 여부 등 | 공고문 본문 표 > 공고페이지 |
| RFP / 과업지시서 | 과업지시서, 설계서, 작성안내서, 평가기준 등 유무 및 열람 방법 | 공고문 본문 > 공고페이지 > 나라장터 게시 자료 |
| 입찰방식 / 성격 | 총액입찰, 전자입찰, 소액수의, PQ, 적격심사, 계속비, 일반경쟁 등 | 공고문 본문 > 공고페이지 |

### 추가 항목 (필요하면 더 적는다)

- 위치
- 공사명/용역명 세부 내용
- 공사구분(예: 종합공사/전문공사, 신설/보수 등)
- 참가자격 요약
- 문의처
- 재입찰/보완 제출 등 특이사항

### 공고 개요가 부족할 때 안내 문구

공고 개요 항목 중 공고문/제출 자료에서 확인되지 않는 내용이 있으면 아래처럼 적는다.

- 확인된 내용만 먼저 채우고, 미확인 항목은 `미확인(제출 자료 기준)`으로 둔다.
- 공고페이지 파일(파일명 예: `공고페이지(…).pdf`)에 해당 내용이 있을 확률이 높다는 사실을 안내한다.
- 가능하면 나라장터 공고문 페이지를 직접 출력해 확인하면 더 정확하다는 점을 함께 적는다.

안내 문구 예시:

> 위 항목 중 일부는 공고문 본문에서 확인되지 않았습니다.  
> 나라장터 공고문 페이지(공고페이지 PDF/게시글)에는 계약명, 발주기관, 기초금액, 접수기간, 과업지시서/설계서 참조 안내 등이 함께 적혀 있는 경우가 많으니, 그 페이지를 다시 확인하거나 출력해 보시면 빠진 항목을 채울 수 있습니다.  
> 지금은 제출된 자료에서 확실하게 명시된 내용만 반영했습니다.

## 3. 참가자격 대조

참가자격 대조는 아래 열 구조로 적는다.

| 항목 | 공고문 요구 조건 | 신청자 현재 상태(프로필 가정) | 부합 여부 | 근거/비고 |

부합 여부는 아래처럼 표시한다.

- `✅ 충족`
- `⚠️ 확인 필요`
- `❌ 불충족`
- `해당없음`

판정 원칙:

- 공고문에서 확실하게 요구된 것만 대조한다.
- 추측하지 않는다. 애매한 지점은 `확인 필요`로 둔다.
- 공고 성격(지원사업 대상자 모집 / 공사 견적제출 / 건설엔지니어링 PQ 등)이 다르면 판정 프레임도 다르게 본다.

## 4. 필요 서류 / 액션 체크리스트

체크리스트는 공고에서 확인된 서류/액션만 넣는다.

- 공고에서 확인되지 않은 서류/액션은 임의로 만들지 않는다.
- 공고만으로 판단이 안 되면 항목을 만들지 말고 `공고 확인 필요`로 남긴다.
- 범용 예시(사업자등록증명, 국세/지방세 완납증명, 4대보험 가입자명부 등)는 공고에서 요구 근거가 확인됐을 때만 넣는다.

표시 방식:

- 공고에서 확인된 서류/액션: `- [ ] 항목`
- 공고 확인이 필요한 항목: `- [ ] 공고 확인 필요: 무엇을 더 확인하면 되는지`

예시:

- `- [ ] 사업신청서`
- `- [ ] 법인등기부등본, 사업자등록증, 영업등록증`
- `- [ ] 공고 확인 필요: 서면평가 시 추가 제출 자료가 있는지 여부`

체크리스트는 눈으로 보고 체크하기 쉬운 빈칸 중심으로 제공한다.
실제 체크 동작(클릭 가능한 컨트롤 등)은 사용 환경에 따라 다를 수 있다.

## 여러 공고 요약 비교표에 넣을 열

여러 공고를 함께 분석할 때는 아래 열을 요약 비교표에 넣는다.

- 공고명
- 기관
- 공고 번호/공고일/접수기간(있으면)
- 사업 성격
- 최종 판정
- 한 줄 판정 요약
- 가장 중요한 결격/보류 사유 1~2개
- 핵심 조건 부합 여부 요약
- 부족 정보 체크포인트 수/종류

요약표에 넣지 않는 것:

- 엑셀 파일 형태 옵션
- 비고/특이사항(필요하면 상세 결과에서 따로 적는다)

요약표는 판정과 이유가 가장 중요하다.
세부 요건 부합 여부, 부족 정보 상세, 서류 체크리스트는 각 공고 상세 파일에서 본다.
부족 정보 체크포인트는 부족할 때 몇 개, 어떤 종류인지만 표시하고 상세는 별도 체크리스트에서 확인한다.

## 공고 개요 작성 시 출처 규칙 요약

1. 제출된 공고문/공고페이지에서 **확실하게 명시된 내용만** 적는다.
2. 공고페이지(나라장터 공고문 페이지) 파일에 내용이 있을 확률이 높으면, 빠진 항목을 채우기 위해 그 페이지를 확인하도록 안내한다.
3. 자료가 없으면 추측하지 말고 `미확인`으로 두고, 나중에 나라장터 공고문 페이지를 출력해 보충할 수 있다고 안내한다.
4. 공고별 식별 정보(공고명, 기관, 공고번호, 공고일, 접수기간)는 가능한 한 함께 남긴다.

## 결과 파일 구성 예시 (엑셀 기준, n+1 시트)

- **요약 시트 1개**
  - 공고명, 기관, 공고번호/공고일/접수기간, 사업 성격, 최종 판정, 한 줄 판정 요약, 핵심 결격/보류 사유, 부족 정보 체크포인트 등
- **공고별 상세 시트 n개**
  - 공고 개요
  - 참가자격 대조
  - 필요 서류/액션 체크리스트
  - 판정 요약 및 부족 정보 안내

예를 들어 공고가 3개면 시트는 4개(요약 1 + 상세 3)로 만든다.
공고 수가 달라지면 그에 맞춰 자동 조정한다.

## 주의사항
- 스캔 PDF는 OCR 품질이 낮을 수 있음. 여러 방법(pdftoppm + tesseract, 전처리 후 재실행) 시도 후 안 되면 미확인 처리
- hwpx 파일은 kordoc 으로 읽되, 파일 확장자만 믿지 말고 실제 형식 확인 (kordoc 이 매직바이트로 판별)
- zip 파일 내 구성 확인 후 각 파일 형식별로 적절한 도구로 읽기
- 공고가 여러 개일 때는 자동으로 합치지 않고 각각 별도 시트로 작성
